# Accessibility

> **Stub.** This is the first slice of the broader a11y work tracked in
> issue #9. Right now it documents the two reusable focus hooks and the
> one modal that opts in (`TodoModal`). It grows as the rest of #9 lands
> (other modals, the color-picker roving tabindex, `axe-core` in tests,
> Playwright keyboard-nav specs, a VoiceOver pass).

## What this covers today

Two hooks give any modal/overlay the baseline keyboard a11y a dialog
needs: focus stays inside while it's open, Escape dismisses it, and focus
returns to whatever opened it when it closes.

### `useFocusTrap(containerRef, enabled = true)`

`src/lib/useFocusTrap.ts`

Guarantees, while `enabled`:

- **Focus is pulled in.** On activation, if focus isn't already inside
  `containerRef`, the first focusable element receives focus. This covers
  the case where the trigger (a button outside the dialog) still holds
  focus.
- **Tab is confined.** Tab past the last focusable wraps to the first;
  Shift+Tab past the first wraps to the last. A Tab pressed while focus
  somehow sits outside the container is pulled back to the first
  focusable.
- **Focus is restored.** On cleanup (unmount or `enabled` → `false`),
  focus returns to the element that was focused when the trap activated —
  i.e. the trigger.

The keydown listener is on `window` (not the container) so a Tab pressed
while focus is on the trigger is still caught. "Focusable" is the usual
set — links, enabled form controls and buttons, and anything with a
non-negative `tabindex`.

### `useEscapeKey(onEscape, enabled = true)`

`src/lib/useEscapeKey.ts`

Calls `onEscape` on the Escape key only, while `enabled`. The listener is
on `window`, so it fires regardless of where focus sits. Pass a stable
`onEscape` (e.g. a `useCallback`) to avoid re-subscribing on every
render.

## How a modal opts in

`src/components/TodoModal/index.tsx` is the reference consumer:

```tsx
const panelRef = useRef<HTMLDivElement>(null);
const headingId = useId();

const requestClose = useCallback(() => {
    /* ...start exit animation, then onClose() */
}, [onClose]);

useFocusTrap(panelRef);
useEscapeKey(requestClose);
```

- `panelRef` is attached to the dialog's content panel (the element that
  contains every focusable control).
- The dialog root carries `role="dialog"`, `aria-modal="true"`, and
  `aria-labelledby={headingId}`, where `headingId` is the `id` on the
  visible `<h2>` heading. (Prefer `aria-labelledby` over `aria-label` so
  the accessible name stays in sync with the on-screen title.)
- Because `TodoModal` only mounts while open, the hooks are always
  enabled there; the `enabled` flag exists for callers that keep an
  overlay mounted and toggle it.

## How it's tested

| Test                                       | Layer       | What it covers                                                                                                                                           |
| ------------------------------------------ | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/lib/useFocusTrap.test.tsx`            | Unit        | Pull-in on activation, Tab/Shift+Tab wrap, focus restore, disabled no-op.                                                                                |
| `src/lib/useEscapeKey.test.ts`             | Unit        | Fires on Escape only, respects `enabled`, re-subscribes, cleans up.                                                                                      |
| `src/components/TodoModal.test.tsx`        | Integration | **Seam (ADR 0008), behavioural:** dialog ARIA, Tab/Shift+Tab trapped, Escape closes and restores focus to the trigger.                                   |
| `src/components/TodoModal.wiring.test.tsx` | Integration | **Seam (ADR 0008), call-pattern:** mocks the hooks and asserts the modal passes the panel ref to `useFocusTrap` and the close handler to `useEscapeKey`. |

The seam tests are the load-bearing ones: the hooks can each pass in
isolation while the modal forgets to wire one up. We keep **both**
flavours deliberately — the behavioural test proves the user-visible
outcome (focus really traps), and the call-pattern test catches
argument-level wiring bugs the behavioural test can't distinguish (e.g. a
stale callback or the wrong ref that happens to behave the same). See
[testing.md](../testing.md) and
[ADR 0008](../decisions/0008-integration-tests-on-the-wiring-seam.md).

## Known gaps (tracked in #9)

- Only `TodoModal` opts in. `LabelsManager`, `ConfirmDialog`, and the
  color-picker popover still need the same treatment.
- No roving-tabindex keyboard nav for the color picker.
- No `axe-core` assertions, Playwright keyboard-nav specs, or VoiceOver
  pass yet.
- **Background siblings aren't `inert`/`aria-hidden`.** The trap confines
  _Tab_, but a screen-reader virtual cursor (notably iOS VoiceOver swipe —
  the primary target) can still wander out of the dialog into the page
  behind it. Marking siblings `inert` while a modal is open is the fix.
- **No visible-focus styling (`:focus-visible`) in this slice.** Trapped
  focus can land on a control with no clear focus ring against the app's
  background; keyboard users may lose track of where they are.
